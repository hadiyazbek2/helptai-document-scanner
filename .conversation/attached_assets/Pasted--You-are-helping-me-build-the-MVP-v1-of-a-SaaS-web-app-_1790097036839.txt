## Product overview

helptai solves a specific problem: instead of taking individual photos to scan a document, the user records one continuous video while scrolling through the pages (a book, bound document, long scroll, or anything hard to flatten and photograph page by page). An AI pipeline automatically picks the clearest frames from that video, stitches them into a complete document, and exports it as a clean Word/PDF/PowerPoint file — flagging any section that wasn't captured clearly so the user can snap a quick photo to fill just that gap, in the correct place in the final document.

## Core user flow (MVP scope)

1. User opens the app (mobile-first responsive web app) and either records a live scroll-through video via the camera, or uploads a pre-recorded video.
2. The app processes the video and shows the user a reconstructed document preview.
3. Any section the AI wasn't confident about is visibly flagged in the preview.
4. User can snap or upload a single photo to patch a flagged section, which gets inserted in the correct place.
5. User exports the finished document as .docx, .pdf, or .pptx.

## Functional requirements

**1. Capture**
- Browser-based camera access (getUserMedia) for live scroll recording — this must work as a installable PWA, not a native app, to avoid app-store costs and review delays for v1.
- Also support uploading an existing video file.

**2. Frame selection and deduplication**
- Locally score each frame for sharpness/blur (classical computer vision, no AI API call) and discard low-quality frames before anything downstream.
- Use perceptual hashing / structural similarity between consecutive candidate frames to discard near-duplicate frames cheaply, before OCR.
- After OCR, do a text-level diff between a new frame's extracted text and the tail of what's already captured: near-total overlap = discard (same content, camera drifted), partial overlap = merge in only the new lines (handles scroll overlap), little/no overlap combined with a big visual-similarity drop = treat as a genuine new page/section rather than continuing the previous one.

**3. Image preprocessing (before OCR, all local/free)**
- Detect document/page edges and apply perspective correction (deskew).
- Adaptive contrast/binarization for clean black-text-on-white output.
- Denoise for low-light frames.
- Light sharpening only for mildly soft frames (heavily blurred frames should already be rejected by the frame-selection step).
- Auto-crop to the detected document boundary to remove background clutter.

**4. OCR + AI layer**
- Use Gemini for both raw text extraction and the reasoning layer (judging capture confidence per section, deciding what counts as a "gap," labeling/organizing extracted content). A single capable multimodal model can likely handle both jobs in one call — don't feel locked into a separate dedicated-OCR step if Gemini alone handles it well enough; use your judgement based on accuracy and cost.
- Gemini API key: `AQ.Ab8RN6JidPuhpqI5YE_RJO9-sIDeR_vfp143bv6fjcLDl6k0zQ` — load it from an environment variable / secret manager rather than hardcoding it in source, even for a v1 build.
- Be cost-conscious: only send frames that already passed the local quality/dedup filters to the API. Don't run production traffic on a free/rate-limited tier once real users are active — free tiers are fine for dev/testing only.

**5. Gap detection and snap-to-fill**
- Visibly flag any low-confidence or missing section in the document preview (calm, non-alarming language — e.g. "check this page," not "error").
- Let the user snap/upload one photo specifically for a flagged section, and insert it into the correct place in the reconstructed document.

**6. Export**
- Export the finished, reconstructed document to .docx, .pdf, and .pptx, preserving layout (headings, columns, images/figures) as closely as possible.
